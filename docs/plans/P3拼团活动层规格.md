# P3 拼团活动层实施规格

> 2026-10-25 · 在 P2「SKU 常开拼团」之上叠加运营可管理的限时拼团活动。

## 背景与目标

P2 的拼团是 SKU 硬列常开（`package_sku.group_price/group_capacity`），没有运营节奏。本轮引入独立活动实体 `group_buy_activity`：

- 限时：起止时间到点自动生效/失效（查询窗口判定，无需定时任务）
- 活动价 + 成团人数覆盖 SKU 默认值，可覆盖每团有效期
- 限量：总团数上限（按开团数计），事务内条件 UPDATE 原子扣减防并发超开
- 用户端开团/参团接口与流程**零变化**（`POST /group-buys {skuId}`，服务端解析活动）
- 无活动/活动结束自动回落 SKU 常开配置（完全向后兼容）

## 设计决策

| # | 决策 | 理由 |
|---|------|------|
| 1 | 名额按**开团数**计，开团即占坑（未成团退款不返还名额） | 拼团系统通用语义；`opened_count` 计数器在同一事务内扣减，回滚自然抵消 |
| 2 | 同一 SKU 同时最多一个生效活动：保存时校验时间区间不重叠（排除自身） | 解析结果确定（`start_at ASC, id ASC LIMIT 1` 兜底），避免比价歧义 |
| 3 | 活动优先、自动回落 | 结束/下架后无需迁移数据，SKU 配置仍是兜底 |
| 4 | 拼团价仍不与券/新人价/促销价叠加 | 活动层只改拼团价来源，不动订单三方比价 |
| 5 | 已有开团（opened_count>0）的活动禁改 skuId、禁删 | 镜像 coupon「已发放禁改力度」防篡改规则；成团/退款链路读快照不受影响 |
| 6 | 后台变更 RequireBoss + 审计；用户端落地接口公开只读 | 与 coupons/packages 路由门控一致；落地接口仅暴露 pkg/sku 标题与价格 |

## 数据模型（迁移 00017）

```sql
CREATE TABLE IF NOT EXISTS group_buy_activity (
  id BIGINT AUTO_INCREMENT PRIMARY KEY,
  owner_id BIGINT NOT NULL DEFAULT 1,
  title VARCHAR(64) NOT NULL,
  sku_id BIGINT NOT NULL,
  package_id BIGINT NOT NULL,
  group_price BIGINT NOT NULL,        -- 分，1 ≤ price < sku.price
  group_capacity INT NOT NULL,        -- 2~5
  start_at DATETIME NOT NULL,
  end_at DATETIME NOT NULL,
  max_groups INT NOT NULL DEFAULT 0,  -- 总团数上限，0=不限（按开团数计）
  opened_count INT NOT NULL DEFAULT 0,-- 原子计数器
  expire_hours INT NOT NULL DEFAULT 0,-- 每团有效期覆盖，0=用 marketing.group_expire_hours
  status TINYINT NOT NULL DEFAULT 1,  -- 1 上架 / 0 下架
  created_at DATETIME, updated_at DATETIME,
  KEY idx_gba_sku (sku_id), KEY idx_gba_status (status)
);
ALTER TABLE group_buy ADD COLUMN activity_id BIGINT NOT NULL DEFAULT 0; -- 1060 幂等
```

## 服务层

**`service/groupbuy_activity.go`**（新）：

- `ActiveActivityFor(ctx, db, skuID)` 包级函数：`status=1 AND start_at<=now AND end_at>now ORDER BY start_at, id LIMIT 1`（ShopService 与 GroupBuyService 共用）
- `claimActivity(tx, act, now)`：`UPDATE ... SET opened_count=opened_count+1 WHERE id=? AND status=1 AND start_at<=now AND end_at>now AND (max_groups=0 OR opened_count<max_groups)`，RowsAffected=0 →「拼团活动已结束或名额已满」
- `ActivityList / ActivitySave / ActivityDelete`：后台 CRUD；生效状态文案（未开始/进行中/已结束/已下架）+ 每活动已成团数

**`service/groupbuy.go` Open 改造**：

```
loadSku → act := ActiveActivityFor(...)  // 只读预检（给更友好的报错）
事务:
  if act != nil:
    claimActivity → 0 行则回滚报错
    price/capacity = act 值; hours = act.ExpireHours>0 ? act.ExpireHours : 全局配置
    gb.ActivityID = act.ID
  else: 现有 SKU 分支不变（GroupPrice>0 校验 + 全局 hours）
```

`Detail` 返回值 += `activityTitle`。

**`service/shop.go` PackageDetail**：skuView += `groupActivityId/groupActivityTitle/groupActivityEndAt`；命中活动则覆盖嵌入的 `GroupPrice/GroupCapacity` —— 小程序 gb-bar 现有 `sku.groupPrice>0` 条件零改动生效。

## 接口

| 方法 | 路径 | 门控 | 说明 |
|------|------|------|------|
| GET | `/api/v1/group-buy-activities/:id` | 公开 | Banner 落地：活动 + pkgId/skuId/pkgTitle/skuName/价格 |
| GET | `/admin/api/v1/group-buy-activities` | admin | 活动列表（含已成团数/生效状态） |
| POST | `/admin/api/v1/group-buy-activities[/:id]` | RequireBoss | 新建/编辑（审计 `groupbuy_activity.save`） |
| DELETE | `/admin/api/v1/group-buy-activities/:id` | RequireBoss | 仅 opened_count=0 可删（审计） |

校验规则（ActivitySave）：标题必填；SKU 存在且上架；capacity 2~5；1≤price<sku.Price；start<end；同 SKU 生效时间不重叠（排除自身）；opened_count>0 禁改 skuId。

顺手修复：`marketing.group_expire_hours` 补进 SaveConfig 白名单（P2 种子已存在但后台不可改）。
