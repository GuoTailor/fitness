# 本地启动指南

> 目标：本地把「后端 + 管理后台 + 小程序」三件套跑起来，体验完整业务闭环
> （建课包 → 限时拼团活动 → 下单支付 → 预约核销 → 评价 → 拼团/裂变/打卡）。
> 全程 mock 模式：无需微信资质、无需商户号，支付/登录/订阅消息全部模拟。

## 0. 前置条件

| 依赖 | 版本要求 | 用途 |
|------|---------|------|
| Go | 1.21+（go.mod 声明 1.26，首次构建会自动补齐工具链） | 编译后端 |
| Node.js | 18+ | 管理后台 |
| MySQL | 5.7+ | 业务库（迁移为 MySQL 方言） |
| 微信开发者工具 | 最新稳定版 | 跑小程序（可选，只想看后台可跳过） |
| Python 3 | 任意 | 可选：跑冒烟脚本造演示数据 |

## 1. 后端 server（:8080）

### 1.1 配置

配置按顺序合并：`configs/config.yaml`（开发默认，已配好）→ `configs/config.local.yaml`（敏感项，**已 gitignore**）→ 环境变量（`DB_PASSWORD` / `JWT_SECRET`）。

`config.yaml` 默认指向开发库 `10.96.158.189`（aos-mysql.dev.svc.cluster.local，库 `fitness`，用户 `fitness`）——本机 `configs/config.local.yaml` 已有该库密码，可直接用。若要改用**自己的 MySQL**，先建库：

```sql
CREATE DATABASE fitness DEFAULT CHARSET utf8mb4;
-- 并给业务账号授权
```

然后新建 `server/configs/config.local.yaml`（只写覆盖项）：

```yaml
db:
  host: 127.0.0.1      # 不写则用 config.yaml 的默认库
  password: "你的MySQL密码"
jwt:
  secret: "任意随机字符串（开发用）"
```

### 1.2 构建与启动

```bash
cd server
go build -o fitness-server.exe ./cmd/server
./fitness-server.exe
```

启动时会自动完成三件事：

1. **跑迁移** 00001~00017（幂等，可反复重启；也可 `./fitness-server.exe -migrate-only` 只迁移不启动）
2. **创建默认管理员** `admin`，密码 `fitness123`（可用环境变量 `ADMIN_INIT_PASSWORD` 覆盖）
3. 监听 `:8080`，日志确认 `wechat.mock=true pay.mock=true`

验证：`curl http://127.0.0.1:8080/healthz` → `{"code":0,...}`

### 1.3 mock 模式语义（重要）

| 开关 | 行为 |
|------|------|
| `wechat.mock: true` | 登录不调微信：**code 即 openid**。传固定 code（如 `mock-user-1`）即稳定身份；传手机号 code 即手机号明文 |
| `pay.mock: true` | 调 prepay 即支付成功并自动入账，无需拉起微信收银台 |
| `notify.mock: true` | 订阅消息只写 `notify_log` 不真正发送，后台「运营配置」可看发送记录 |

## 2. 管理后台 admin-web（:5173）

```bash
cd admin-web
npm install
npm run dev
```

浏览器打开 http://localhost:5173 ，登录 `admin / fitness123`。vite 已配置代理（`/api` 与 `/admin/api` → `127.0.0.1:8080`），无需跨域设置。

**建议体验路径**：

1. **课包管理**：新建课包 + SKU，SKU 行内可配「新人价 / 限时活动价（带起止时间）/ 拼团价 + 成团人数（2~5）」
2. **拼团活动**（P3 新增）：对某 SKU 新建限时拼团活动——活动价/人数覆盖 SKU 常开拼团，可设总团数上限与每团有效期；到点自动生效/失效，无需手动上下线
3. **优惠券**：建满减/折扣/赠课券模板，配合领券中心与定向发放
4. **订单管理 / 拼团管理 / 老带新邀请 / 运营配置**：观察小程序端操作后的数据流

## 3. 小程序 miniprogram（微信开发者工具）

1. 微信开发者工具 →「导入项目」→ 选择仓库下的 `miniprogram/` 目录；appid 用测试号即可（`project.config.json` 已是 `touristappid`）
2. 右上角「详情」→「本地设置」→ 勾选 **不校验合法域名、web-view（TLS 版本）以及 HTTPS 证书**（本地 apiBase 是 http）
3. 后端地址在 `miniprogram/app.js` 的 `apiBase`，默认 `http://127.0.0.1:8080`，本机启动无需改动；**真机预览**时改成电脑的局域网 IP（如 `http://192.168.x.x:8080`）并保证手机与电脑同网
4. **登录**：mock 模式下工具自带的 `wx.login` 每次返回不同 code = 每次都是新用户。要稳定身份，用首页底部「**开发：指定 mock 身份登录**」输入框：
   - `mock-user-1` —— 学员身份（固定）
   - `mock-coach-1` —— 教练身份（需后台已建教练并绑定该账号）
   - 任意新串（如 `mock-user-me`）—— 造一个新学员
5. 主流程：首页/课包商城 → 课程详情（选 SKU、领券、拼团入口）→ 下单（mock 即支付成功）→ 团课课表/找教练预约 → 我的（课时、拼团、邀请卡、教练入驻）

## 4. 一键造演示数据（可选）

想跳过手工建数据直接看"满数据"效果，跑冒烟脚本（它会把课包、拼团+限时活动、裂变绑定、打卡、评价、入驻全链路各造一遍）：

```bash
python scripts/smoke_p3.py
```

- 脚本使用默认管理员 `admin / fitness123`，后端需已在 :8080 运行
- 登录接口有**每分钟 10 次/IP 限流**：若脚本报 403，等 60 秒重跑即可
- 连续跑多套脚本时（p1/p2/m3/m4/p3），两套之间 `sleep 60`

## 5. 常见问题

| 现象 | 处理 |
|------|------|
| 启动报「数据库密码为空」 | 没配 `config.local.yaml` 或 `DB_PASSWORD`，见 1.1 |
| 登录 403 / 次数超限 | 登录限流 5 次失败锁 15 分钟（管理员）、用户登录 10 次/分/IP，等窗口再试 |
| 小程序请求失败 | 确认「不校验合法域名」已勾选、后端已启动、`apiBase` 与实际端口一致 |
| 图片上传后不显示 | 文件落在 `server/data/uploads/`，开发模式由服务直出 `/uploads/`，确认没改 `upload.base_url` |
| 端口冲突 | 改 `config.yaml` 的 `server.port`，同步改 `admin-web/vite.config.js` 代理 target 与 `miniprogram/app.js` 的 apiBase |
| 迁移中断/报错 | 迁移幂等（表/列/键已存在自动跳过），修复连接后重启即可续跑 |
| 想清空重来 | 业务数据表清空后重启服务，迁移与默认管理员会自动恢复（迁移脚本本身不会重复执行数据种子，如需种子可对 `app_config` 等表按迁移文件手工补插） |

## 6. 上线提醒（本地体验不涉及）

mock 模式仅用于本地开发。上线需按 `docs/plans/上线checklist.md` 办理：企业认证小程序 + 域名备案与 HTTPS、`config.production.yaml` 关闭全部 mock 并填真实 AppID/Secret/商户号/订阅消息模板、`ADMIN_INIT_PASSWORD` 设置强密码。资金相关（支付回调验签 + 幂等、退款审批链路）已按真实通道实现，切配置即启用。
